# Blogus Development Checkpoints

本文档用于沉淀 Blogus 的阶段开发计划和验收项。每个阶段完成后，应按对应检查点逐项确认，再进入下一阶段。

## 阶段 0：基线梳理与质量门禁

目标：确认现有骨架可维护，建立后续每阶段的验收基线。

完成记录：

- 2026-06-11：已在 `README.md` 补充本地准备、端口、依赖服务、环境变量、API/Web/CLI 当前状态、质量门禁和非生产能力说明。
- 2026-06-11：已将 Vite `/api` 代理端口对齐到 API 默认端口 `3009`。
- 2026-06-11：已补齐类型依赖和服务端类型收窄，`pnpm typecheck` 通过。

开发项：

- 明确环境变量、启动方式、端口、依赖服务说明。
- 梳理 API、Web、CLI 当前功能清单。
- 固定基础检查脚本约定，例如 `pnpm typecheck`、`pnpm build`。
- 标注 dev-only 能力，例如 `dev-login`、device auth placeholder。

验收项：

- [x] `README.md` 能让新开发者完成本地准备。
- [x] 项目约定 `pnpm typecheck` 作为每阶段必过项。
- [x] API 路由、页面、CLI 命令的当前状态有清晰记录。
- [x] 明确标出哪些能力还不能用于生产。
- [x] 不执行构建镜像、启动容器等非纯代码任务，除非用户显式确认。

## 阶段 1：数据持久化与文章核心能力

目标：把文章 CRUD 从内存实现迁移到 PostgreSQL/Drizzle，形成可重启、可验证的内容数据闭环。

开发项：

- 使用现有 Drizzle schema 落地 `users`、`posts` 表。
- 将文章列表、创建、编辑、发布、删除接入数据库。
- 支持 slug 生成、唯一性处理、发布时间、草稿和发布状态。
- 统一 API 返回结构和错误格式。
- 前端首页只展示已发布文章。
- 管理端展示草稿和已发布文章。
- CLI `post list/create/edit/publish` 与 API 行为保持一致。

验收项：

- [x] 重启服务后文章仍然存在。
- [x] 可以通过 CLI 创建草稿、编辑正文、发布文章、删除文章。
- [x] 首页不会展示草稿文章。
- [x] 管理端可以看到草稿和已发布文章。
- [x] CLI 和 Web 管理端操作同一份数据库数据。
- [x] slug 为空标题、重复标题、特殊字符标题都有稳定处理。
- [x] 找不到文章时返回明确的 404 错误。
- [x] 输入不合法时返回明确的 400 错误。
- [x] `pnpm typecheck` 通过。
- [x] 核心文章路由有测试覆盖，至少包含创建、列表、更新、删除。

## 阶段 2：认证与权限

目标：替换开发友好的登录占位，实现可控的管理员访问。

完成记录：

- 2026-06-11：已实现邮箱密码登录、scrypt 密码哈希、首个注册用户成为管理员、邀请码注册、access/refresh token cookie、refresh 轮换和登出会话吊销。
- 2026-06-11：已新增 `auth_sessions` 表，access token 必须绑定有效 session；文章管理列表、文章写操作和上传均要求鉴权。
- 2026-06-11：已将 CLI 登录从 device placeholder 改为邮箱密码或 token 登录模式，`logout` 会尝试吊销服务端会话。
- 2026-06-11：已限制 `dev-login` 在生产环境不可用；生产环境默认 `JWT_SECRET=dev-secret` 会启动失败。
- 2026-06-11：`pnpm typecheck` 通过；服务端文章路由测试通过，覆盖未登录管理/写操作拒绝。

开发项：

- 实现真实用户登录，至少支持邮箱和密码。
- 密码使用安全哈希存储。
- 管理端、上传、文章写操作必须鉴权。
- 按环境限制或移除 `dev-login`。
- 完善 access token、refresh token 轮换和登出。
- CLI 登录流程从 placeholder 改成真实授权流程，或先提供 token 登录模式。

验收项：

- [x] 未登录用户不能访问管理写操作。
- [x] 未登录用户不能上传文件。
- [x] 登录后 cookie 鉴权和 refresh 流程正常。
- [x] 登出后旧会话不能继续写入。
- [x] CLI 能完成登录、`whoami`、发文。
- [x] 生产环境不会启用 `dev-login`。
- [x] 安全相关环境变量缺失时服务明确失败。
- [x] `pnpm typecheck` 通过。

## 阶段 3：内容编辑与媒体管理

目标：让 Blogus 可以完成日常写作、插图、预览、发布流程。

完成记录：

- 2026-06-11：管理端已升级为文章工作台，支持创建、选择、编辑、Markdown 预览、上传封面、上传插图、发布、撤回和删除。
- 2026-06-11：文章模型已补齐 `excerpt`、`coverImageUrl`、`tags`，API 和 CLI 创建/编辑均支持这些字段。
- 2026-06-11：已新增公开文章详情页 `/posts/:slug` 和 `GET /api/posts/:slug`；公开读取只返回已发布文章，管理态 `visibility=all` 仍需登录。
- 2026-06-11：Markdown 由前端 React 组件渲染，不使用 `dangerouslySetInnerHTML`，危险 HTML 会作为文本处理。
- 2026-06-11：本地上传仍为默认存储，MinIO/S3 兼容存储仍通过 `STORAGE_DRIVER=minio` 可选启用；未执行容器启动或对象存储运行态验证。
- 2026-06-11：`pnpm typecheck` 通过；服务端路由测试通过，覆盖按 slug 读取已发布文章且不公开草稿、文章元数据、撤回发布。

开发项：

- 管理端支持文章列表、编辑、发布、撤回、删除。
- 支持 Markdown 编辑与预览。
- 上传图片到本地磁盘或 MinIO/S3，并在文章内容中插入 URL；开发默认使用本地磁盘。
- 增加 excerpt、封面图、标签或分类的最小模型。
- 文章详情页支持按 slug 访问。

验收项：

- [x] 管理端可完成“写作 -> 插图 -> 预览 -> 发布”闭环。
- [x] 默认本地存储能保存文件并返回可访问 URL。
- [x] MinIO/S3 可作为可选存储后端启用，不作为开发默认依赖。
- [x] 文章详情页刷新后仍可直接访问。
- [x] Markdown 渲染安全，不直接执行危险 HTML。
- [x] Web 和 CLI 创建的文章都能在前台正确展示。
- [x] 空内容、长标题、长正文有合理 UI 表现。
- [x] `pnpm typecheck` 通过。

- 增加空状态、加载态、错误态。

验收项：

开发项：

- 说明备份策略：PostgreSQL 数据、本地上传目录、可选 MinIO 数据。

验收项：

- [ ] 新机器按文档可以完成部署准备。
- [ ] 健康检查能反映 API、DB、当前存储后端状态。
- [ ] 迁移可重复执行，不破坏已有数据。
- [ ] 构建产物可运行。
- [ ] 备份和恢复流程有文档或脚本说明。

- [ ] `pnpm build` 通过。

## 阶段 6：生产安全加固

目标：把“能用”升级到“敢长期用”。

开发项：

- 配置 CORS、secure cookie、sameSite、生产域名。
- 限制上传文件大小、类型、路径。
- 增加 API rate limit。
- 实现首个注册用户成为管理员的初始化流程。
- 审计敏感默认值，例如 JWT secret、公开 bucket、dev auth。
- 错误信息脱敏。

验收项：

- [ ] 生产环境不能使用默认弱密钥启动。
- [ ] 未授权请求没有敏感信息泄露。
- [ ] 上传恶意文件、超大文件、非预期类型会被拒绝。
- [x] 管理员初始化有明确一次性流程。
- [ ] 基础安全 checklist 全部通过。
- [ ] `pnpm typecheck` 通过。
